# AGENTS.md

figkit is a toolbox for webapps that are the interactive counterparts of scientific papers: a
Python package that exports data, builds sites and runs JS tests, carrying a browser library of
plain ES modules. Read `.specify/memory/constitution.md` first; it overrides everything here.

## How work is done here

This repo uses [Spec Kit](https://github.com/github/spec-kit) v1.1.3 (`.specify/`, commands as
`.claude/skills/speckit-*`). A feature goes `/speckit-specify` → `/speckit-plan` → `/speckit-tasks`
→ `/speckit-implement`, in `specs/NNN-name/`. Small fixes that change no public API go straight to
a pull request.

## Layout

```
src/figkit/            Python: data.py (export/load), build.py (build, inline_modules, checks),
                       serve.py, cli.py (build/serve/test), anywidget.py (notebook Widget)
src/figkit/js/         browser library (package data, vendored into built sites):
                       figkit.js model.js npy.js data.js geom.js stage.js globe.js skypanel.js figkit.css
src/figkit/node/       Node-only test tooling for `figkit test` (resolve hooks); never shipped to browsers
examples/globe/        the globe example (also the gallery entry and acceptance test); prototype/ is
                       the page it replaced, kept for reference
examples/gallery.py    the gallery's index page
skills/figkit/         skill: building a webapp (references/, assets/template/)
skills/figkit-upgrade/ skill: moving a webapp to a newer figkit tag
tests/                 pytest (test_smoke.py: browser tests, marker `smoke`); make_fixtures.py
js-tests/              node --test (fixtures generated by tests/make_fixtures.py)
package.json           test-only: lets Node resolve figkit/… inside this repo (no dependencies)
CHANGELOG.md           every release; migration notes for breaking changes (shipped in the wheel)
```

## Conventions that are easy to break

- JS modules import each other only by bare specifiers (`figkit/model.js`, `app/science.js`), never
  `./x.js`, and never use `import.meta.url` (except Node tooling in `src/figkit/node/`).
  `figkit build` rejects violations; it also checks figkit's own modules.
- No DOM access at module top level. Pure kernels (shading, autoscale, geometry) are exported
  separately from `mount` so Node can test them.
- Components export `mount(el, model, opts) → dispose`; model values are replaced, never mutated.
- Science-specific code stays in apps (`science.js`), never in figkit.
- Code enters figkit only when a real app needs it.

## Testing

```bash
uv run pytest                                                  # not the smoke tests
uv run python tests/make_fixtures.py && node --test js-tests/*.test.js
uv run pytest -m smoke --browser chromium --browser webkit     # Firefox runs in CI
```

## Releasing

Releases follow the `versions/vX.Y.x` model (as in phasecurvefit and unxt), so a paper pinned to
`vX.Y.Z` can get bug fixes without the next minor version's breaking changes.

**A minor (or major) release, `vX.Y.0`, from `main`:**

1. In a pull request: set `__version__` in `src/figkit/__init__.py`, and add the
   `## X.Y.0 — YYYY-MM-DD` section to `CHANGELOG.md`. Every breaking change needs a migration note
   (**What changed**, **Find**, **Edit**); public-API changes update both skills.
2. Squash-merge it (the only method `main` allows), then tag the merge commit and branch from it:
   ```bash
   git tag -a vX.Y.0 <sha> -m "figkit X.Y.0" && git push origin vX.Y.0
   git branch versions/vX.Y.x vX.Y.0 && git push origin versions/vX.Y.x
   ```
3. `gh release create vX.Y.0 --verify-tag` with the changelog section as notes; `gallery.yml`
   deploys the examples to Pages. CI checks that the tag equals `v` + `__version__`.

**A bug-fix release, `vX.Y.Z` (Z > 0), from `versions/vX.Y.x`:**

1. Fix on `main` first (pull request), unless the bug no longer exists there.
2. Backport: a pull request into `versions/vX.Y.x` cherry-picking the fix, bumping `__version__` to
   `X.Y.Z` and adding a `## X.Y.Z` changelog section (on `main` too, so its changelog stays complete).
   Bug-fix releases never contain breaking changes.
3. Tag the merged commit on `versions/vX.Y.x` as `vX.Y.Z`, push, and create the release.

## Pull-request previews

Every pull request gets a live preview of the gallery on Cloudflare Pages (project `figkit`,
branch `pr-<number>`), posted as a sticky comment by the `preview` job in `tests.yml`. It needs the
repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` and skips without them. The
one check to require in branch protection is **CI Pass**.
